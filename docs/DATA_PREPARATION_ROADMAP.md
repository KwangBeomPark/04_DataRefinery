# 데이터 정제·데이터 마트 제작을 위한 앱 개선 계획

작성: 2026-10-15. 대상: 소스 v2.0.3. Claude Opus 5.5와의 논의 및 현재 소스·합성 자료 화면 점검을 바탕으로 한 제품 계획입니다.

**2026-10-16 진행:** A단계 중 원본 저장 경로 보호와 숫자 표기·엄격 검사, 프리셋 연계의 첫 구현을 반영했습니다. 아래 §5의 해당 두 위험은 발견 당시의 기록이며 후속 조치와 한계는 [A단계 검수 기록](PHASE_A_SAFETY_REVIEW.md)을 참고하세요. 기간 형식·배포 검수 UI 등 A의 나머지와 정제 탭은 후속 작업입니다.

## 1. 방향과 이번 변경의 범위

이 앱의 중심 업무를 **큰 원본을 분석에 맞게 정리하고, 검증한 데이터셋을 기간별로 누적하여 Excel에 공급하는 일**로 정합니다.

이번에 구현한 것은 기존 네 탭의 순서 변경과 버전 갱신입니다.

**데이터 집계·슬라이서 → 데이터셋 배포 → 프로모션 템플릿 → CSV 구조 복구**

Qt 기본 화면과 Tkinter 호환 화면에 같은 순서를 적용합니다. 첫 화면은 집계입니다. 한국어·영어·폴란드어 전환은 탭의 위치가 아닌 실제 업무에 연결합니다. 새 정제 탭, 출력 정의, 화면 개편 등 아래 기능은 **제안**이며 아직 구현된 기능이 아닙니다. v2.0.3은 소스 준비 상태이고 이 문서는 새 서명 설치본·태그·실게시의 증거가 아닙니다.

운영 전제는 다음과 같습니다.

- 제작 담당자는 이 앱으로 정제·누적·검수·배포합니다. 분석 담당자는 Microsoft 365 64비트 Excel의 기본 Power Query·피벗 기능을 사용합니다. 분석 담당자에게 Python·DuckDB·ODBC 설치를 요구하지 않습니다.
- 업무 데이터는 회사 공유 폴더에 배포합니다. SharePoint·외부 클라우드 업로드·DB 서버 도입을 이번 기본안으로 삼지 않습니다.
- 앱의 설정·로그는 설치 경로 아래 `UserSetting`, 작업 DB는 `UserSetting/datasets`에서 관리합니다. 공유 폴더의 DuckDB 파일을 여러 Excel 사용자가 직접 여는 방식으로 바꾸지 않습니다.
- 보존 기간은 연간/3개년으로 미리 고정하지 않습니다. 실제 데이터 크기와 분석 기간을 측정한 뒤 정하며 기본값으로 과거 데이터를 자동 삭제하지 않습니다.

## 2. 사용자 관점의 완성 흐름

```mermaid
flowchart LR
    A[원본 CSV 읽기] --> B[정제 규칙과 품질 확인]
    B --> C[요약·상세 출력 정의]
    C --> D[데이터셋별 기간 누적]
    D --> E[전체 검수와 승인]
    E --> F[공유 폴더 배포]
    F --> G[각자의 Excel에서 새로고침·피벗]
```

예를 들어 큰 연간 자료 한 개에서 다음 결과를 정의합니다.

| 결과 | 데이터 한 행의 의미 | 핵심 처리 |
| --- | --- | --- |
| 거래선 손익 요약 | 합의한 기간 × 거래선 × 필요한 법인/통화 등 | 모델 열을 제외하고 매출·영업이익 등 합산 가능한 수치를 집계 |
| TV 상세 | 필터를 통과한 원본의 한 행 | TV만 선택하고 필요한 열·모델 정보를 유지 |
| 냉장고·세탁기 상세 | 각 사업부의 원본 한 행 | 사업부별로 나누며 정당한 중복 행도 유지 |
| 기타·미분류 점검 | 어느 출력에도 포함되지 않은 원본 행 | 제외 사유와 수치 영향을 확인 |

**요약과 상세를 같은 작업으로 취급하지 않습니다.** 모든 열을 묶기 키로 넣는 방식은 원본 상세 보존을 대신할 수 없습니다. 누락된 순이익을 임의로 만들거나 서로 다른 통화·단위의 금액을 합치지 않습니다. 비율은 비율끼리 합산하지 않고 승인한 분자·분모로 다시 계산합니다.

## 4. 기존 탭 보강과 신규 탭의 경계

### 권장: 정제 전용 탭 하나 추가

| 화면 | 맡길 일 | 상태 |
| --- | --- | --- |
| 데이터 정제 | 열 선택·이름/형식 지정, 공백·날짜·숫자 정규화, 결측 처리 정책, 업무 분류 매핑, 순서가 있는 규칙 편집 | 신규 제안 |
| 집계·출력 | 빠른 집계 + 등록 출력 정의 편집. `요약` 또는 `원본 행 유지 상세` 선택, 필요한 열·필터·사업부 분할 정의 | 기존 집계 탭 확장 제안 |
| 데이터셋·배포 | 등록된 정의 선택, 입력 변경 확인, 고정 계획 실행, 기간 누적, 검수, 승인, 공유 배포와 Excel 연결 | 기존 배포 탭 재구성 제안 |
| 프로모션 템플릿 | 기존 기간별 기준 규칙·일별 전개 업무 | 기존 기능 유지 |
| CSV 구조 복구 | 구분자·인코딩·깨진 행 등 입력 구조 문제 해결 | 기존 기능 유지 |

신규 탭 도입 후 후보 순서는 **정제 → 집계·출력 → 데이터셋·배포 → 프로모션 → CSV 복구**입니다. 이는 후속 화면 설계안이며 이번 네 탭 재배치를 다시 바꾼 것이 아닙니다.

품질 검사·이력·기준 정보는 관련 화면 안에 두고 처음부터 별도의 주 탭으로 늘리지 않습니다. CSV 복구는 입력 문제 발생 시 정제 화면에서 이동할 수 있게 하고, 프로모션 결과도 필요하면 일반 입력으로 연결합니다. 차트·통계 분석·OLAP 서버 기능을 추가하는 대신 Excel에서 분석하기 좋은 결과를 만드는 데 집중합니다.

### 탭은 편집 장소, 실행은 공통 작업

정제 탭에서 CSV를 저장하고 집계 탭에서 다시 고르고 배포 탭에서 또 설정하는 반복을 기본 동선으로 만들지 않습니다. 데이터셋 작업에 입력·정제 규칙·출력 정의를 연결하고 공통 실행기가 처리합니다.

- 정제 탭은 **규칙을 작성**합니다.
- 집계 탭은 **결과의 모양을 작성**합니다. 현재처럼 파일 하나를 빠르게 집계하는 모드도 유지합니다.
- 배포 탭은 등록된 계획을 **실행·누적·검수·배포**합니다. 변환 규칙을 다시 편집하는 화면을 중복 구현하지 않습니다.
- 빠른 집계 결과는 자동으로 공식 데이터 마트가 되지 않습니다. 설정을 등록 작업으로 저장하고 전체 검수·승인 절차를 거쳐야 합니다.

`AggregationSpec`, `data_mapper`, `DatasetEngine`, `BackgroundJobRunner`를 재사용하되 파일 기반 집계와 데이터셋 스냅샷을 연결하는 어댑터를 별도로 설계합니다. 기존 엔진 전체를 한 번에 다시 쓰는 계획은 아닙니다.

기존 배포 마법사와 CSV 데이터셋은 호환을 유지합니다. 새 출력부터 정의 참조로 점진적으로 연결합니다. 개념상 **작업 계획은 입력·정제 규칙**, **출력 정의는 결과별 스키마·행 단위·키·목적지**, **누적 데이터셋은 해당 출력 하나의 이력**을 맡습니다. 행 단위나 스키마가 다른 요약과 상세를 같은 누적 테이블에 섞지 않습니다.

이 중 두 위험은 **새 합성 자료만으로 재현**했습니다. `1.234,56`이 English 해석에서는 `1.23456`, Polish 해석에서는 `1234.56`이 됐고, 공백 천 단위 값은 English 해석에서 변환 실패가 됐습니다. 합성 원본과 같은 출력 경로를 지정하자 두 행 원본이 한 행 요약으로 교체됐습니다. 실제 업무 원본은 사용하지 않았습니다. 후속 정식 배포 전 우선 수정할 항목이며 이번 탐색 순서 변경으로 새로 생긴 문제는 아닙니다.

화면 관찰은 합성 자료를 사용한 Qt offscreen 980×880·820×720 렌더에 한정합니다. OS 폰트를 별도로 로드했으며 이모지 네모는 실제 제품의 글꼴 결함으로 판정하지 않았습니다. Windows 실화면·배율별 사용성 검수를 대신하지 않습니다.

## 6. 화면별 구체적인 개선안

### 데이터 정제: 표를 보며 수정하는 한 화면

- 상단: 입력 파일/폴더, 기간·인코딩·숫자 해석, `표본 미리보기` / `전체 검사` 구분.
- 왼쪽: `열 선택 → 이름·형식 → 값 정리 → 분류 매핑 → 품질 정책`처럼 순서가 보이는 단계. 단계 삭제·재정렬 시 이후 결과를 다시 계산합니다.
- 중앙: 원문과 정제 결과를 비교하는 표. 거래선·모델 코드는 텍스트를 유지해 앞자리 0을 보호합니다.
- 오른쪽/하단: 빈값·중복·형식 오류·미분류 건수와 대표 사례. 어느 범위를 검사했는지 표시합니다.
- 주 작업: 처음에는 `전체 검사`, 성공 후 `작업에 저장`. 원본은 읽기 전용이며 제외·격리한 행의 사유와 수치 영향을 남깁니다.

MVP 입력은 큰 CSV를 우선합니다. Excel 입력은 후속 단계에서 시트 선택·행 제한·읽기 전용 처리를 따로 검증합니다. 임의 Python/SQL 코드를 입력하는 방식보다 허용된 변환 규칙을 저장하는 방식으로 시작합니다.

### 집계·출력: 요약과 상세를 먼저 구분

- `요약 만들기` / `원본 행 유지`를 명확히 선택하게 합니다.
- 요약은 묶기 기준과 수치 함수, 상세는 남길 열·행 조건·분할 기준을 보여줍니다.
- 원본 필드 선택 후 `추가` 버튼, 선택 항목 옆 `제거`, 집계 함수 선택을 제공합니다.
- 결과 미리보기와 저장 예상 행 수를 구분합니다. 예상치·표본 결과를 확정 전체 행 수로 표시하지 않습니다.
- 완료 후 `출력 정의 저장`과 `이 정의로 데이터셋 등록`으로 이어집니다. 이미 승인한 정의를 바꾸면 재검수가 필요합니다.

### 데이터셋·배포: 관리 목록과 다음 작업

- 왼쪽: 데이터셋명·포함 기간·실제 상태·마지막 성공 배포. 처음에는 예제 설명과 `새 데이터셋` 행동을 표시합니다.
- 오른쪽 상단: 선택한 데이터셋의 목적, 입력·공유 경로 복사/열기, 공개 버전과 마지막 성공 정보.
- 가운데: 추가/교체할 기간, 반영 전후 행 수·합계, 경고·차단 사유를 표로 표시합니다. 숨겨진 경고를 성공 문구로 대체하지 않습니다.
- 상태는 `변경 확인 필요 → 변경 있음 → 검수 중 → 검수 실패/통과 → 승인됨 → 배포됨`, 별도로 `승인 후 변경됨`을 둡니다.
- 상태에 맞는 주 행동은 하나만 강조하되 승인과 배포는 각각 명시적으로 실행합니다. 멈춤·재시도·실패가 기존 공개 자료에 미친 영향을 알려줍니다.
- 완료 화면은 CSV 배포와 Excel 템플릿 생성을 구분하고, 분석 담당자에게 전달할 파일·경로·새로고침 안내를 제공합니다.

## 7. 데이터 마트가 되기 위한 최소 계약

각 작업에는 다음을 저장합니다.

1. **입력:** 원본 경로·파일 집합·기간·인코딩·구분자·내용 지문. 크기/수정 시각은 빠른 변경 탐지용이며 승인 시 내용 검증을 대신하지 않습니다.
2. **열과 행의 의미:** 열 이름·자료형·단위·통화, 한 행의 업무 단위, 식별 키와 고유성 정책. 거래 상세의 정당한 중복은 자동 삭제하지 않습니다.
3. **정제:** 순서가 있는 레시피와 버전, 숫자·날짜·빈값·중복·미분류 처리 정책. 오류를 0이나 임의 날짜로 자동 교체하지 않습니다.
4. **출력:** 고정 ID, 요약/상세 종류, 필터·선택 열·분할 조건·집계식과 표준 CSV 규격. 정밀도는 열별로 합의하며 금액 대조에 임의 부동소수 오차를 숨기지 않습니다.
5. **검수:** 전체 결과 행 수, 고유 업무 키 수, 기간별 수치, 제외/격리 행, 대조 범위와 차이. 허용 오차가 필요하면 이름·값·사유를 명시합니다.
6. **실행과 승인:** 입력·레시피·출력·스키마·앱 버전과 실행 스냅샷을 고정한 실행 지문. 승인은 지문·검수 결과·완성한 출력 내용 해시에 묶습니다. 배포는 승인한 결과를 복사하고 다시 계산하지 않습니다. 복사 직전에 결과 해시를 대조하고 원본/정의가 바뀌었으면 `승인 후 변경됨`으로 차단합니다. 초기 승인은 담당자 한 명의 명시적 기록이며 이중 승인 체계를 뜻하지 않습니다.
7. **배포:** 결과의 내용 해시, 원천 스냅샷/정의 버전, 배포 성공 시각과 실제 공유 경로. 일부 출력의 성공을 전체 배포 성공으로 표시하지 않습니다.

정의 해시는 다음 달에도 재사용하는 레시피·출력 정의의 지문이며 실행 지문은 정의 해시·입력 내용 해시·앱/정의 스키마 버전을 포함합니다. 초기에는 별도 엔진 버전 체계까지 만들지 않습니다. JSON 객체의 키만 정렬하고 배열의 단계·열 순서는 보존하며, 수치 설정은 십진 문자열로 저장합니다. 실행 시각은 실행 지문에서 제외합니다.

같은 입력·규칙의 재실행은 논리적 결과·행 수·합의한 십진 정밀도의 대조 합계가 같아야 합니다. 임의 반올림으로 차이를 숨기지 않습니다. CSV 바이트 해시까지 같게 요구하는 출력은 상세를 원본 파일/행 번호 순서, 요약을 묶기 키 순서로 정렬하고 숫자 서식·인코딩·줄바꿈을 고정합니다. 실행 시각 같은 메타데이터는 비교에서 분리합니다. 객체 키의 나열 순서 변경과 배열 안의 단계/열 순서 변경을 혼동하지 않습니다.

요약과 상세의 합계 대조는 **동일 기간·통화·단위·원천 범위**일 때만 성립합니다. TV·냉장고·세탁기가 전체 사업부를 포괄하지 않으면 기타/미분류를 별도로 계산하거나 비교 범위를 제한합니다. 서로 다른 집계 수준의 순이익을 모델 상세에 임의 배분하지 않습니다.

각 출력은 먼저 **같은 정제 입력에 같은 필터를 적용한 기준값**과 대조합니다. 전체 사업부 거래선 요약을 TV 상세 하나와 직접 비교하지 않습니다. 요약에 사업부 기준이 있거나 TV 범위로 제한했을 때만 TV 상세와 직접 대조합니다. 행 수 설명은 `원본 = 대상 상세 + 기타/미분류 + 격리 + 명시적 제외`로 하며 범주가 서로 겹치지 않게 합니다.

## 8. 기술 적용과 안전한 공유 방식

- 현재 pandas 청크 집계와 DuckDB 누적 기반을 유지합니다. 신규 정제는 공통 계획의 어댑터로 연결하고 전체 자료를 GUI 스레드나 pandas 한 덩어리로 무조건 읽지 않습니다.
- 문자열 코드, 열별 숫자 표기와 금액 정밀도를 먼저 확정합니다. 내부 typed 작업 테이블과 배포 CSV에서 다른 의미로 해석되지 않게 변환 실패·스키마 변경을 차단합니다.
- 같은 종류 파일의 기간 누적은 기존 기능을 보강합니다. 다른 표의 열을 붙이는 조인은 별도 작업이며 처음에는 기준 표의 키 고유성이 보장되는 N:1부터 검증합니다.
- 모든 탭은 같은 작업 실행·취소·진행·오류 계약을 사용합니다. 작업 DB는 앱이 관리하고 쓰기를 직렬화합니다. GUI의 선택 변경이 실행 중 계획을 바꾸지 못하게 합니다.
- 원본·정제 전체를 각각 영구 복제하는 저장 방식을 기본으로 강제하지 않습니다. 원본은 외부 읽기 전용 입력, DB는 작업용이며 승인 대기 스냅샷은 보존합니다. 작업이 확정되거나 안전하게 되돌린 후에만 임시 공간을 정리합니다.
- 전체 실행 전 작업 디스크의 여유 공간을 확인합니다. 가능한 읽기 스트림·검증된 로컬 임시 사본에서 내용 해시를 계산하여 공유 원본의 반복 전체 읽기를 줄이되, 승인 검증을 생략하는 성능 최적화는 하지 않습니다.
- 지문만 저장해서는 사용자가 바꾼 과거 원본을 재생성할 수 없습니다. 과거 재현이 필요하면 원본 보관 정책을 추가로 정해야 합니다. 배포 버전 보존과 원본 보존은 다른 정책입니다.
- Excel은 데이터셋별 고정된 `current` CSV 경로에 연결합니다. 내부 `versions`나 원본 폴더까지 무차별로 합쳐 중복 읽지 않게 템플릿의 파일 범위를 고정합니다.
- CSV를 읽기 전용으로 연결해도 새로고침 때 읽는 양은 남습니다. 용도별 요약·상세·기간 선택으로 필요한 양을 줄이고 실제 Excel 새로고침을 측정합니다. CSV를 OLAP/DB 서버와 동일한 선택 조회 방식으로 설명하지 않습니다.
- 초기 배포는 산출물별 검증·안전 교체와 명시적 상태를 우선합니다. 여러 CSV와 매니페스트의 일괄 갱신을 공유 파일시스템 전체의 단일 트랜잭션으로 보장하지 않습니다. 여러 결과를 동시에 읽어야 하면 같은 원천 버전 확인·게시 완료 표시·소비자 새로고침 정책을 별도로 설계합니다.

### 다음 개발 세션과 첫 완성 사례

다음 세션에서는 우선 **원본 동일 경로 차단과 숫자 해석** 두 항목을 완성합니다. 동일 실제 파일·상대 경로·대소문자 차이·파일 별칭을 검토하고 원본 해시가 보존되는지 검사합니다. 숫자 표기 선택을 작업과 프리셋에 저장하고 국제 표기의 잘못된 크기 해석 및 변환 실패를 샘플에서 드러냅니다. `1.234,56`을 조용히 `1.23456`으로 읽는 사례를 통과로 간주하지 않습니다.

그다음 B단계의 첫 사례는 **로컬 결과까지만 만드는 작은 작업**입니다. 곧바로 다섯 탭을 모두 개편하거나 공유 배포까지 한 번에 연결하지 않습니다.

1. 앞자리 0인 거래선 코드, 폴란드식 금액, 같은 TV 행 두 개, 기타 사업부, 통화 두 종류, 금액 오류 한 행의 합성 입력을 준비합니다.
2. 최소 레시피와 출력 정의를 저장해 `기간 × 거래선 × 통화` 요약 및 원본 행을 보존한 TV 상세를 로컬 임시 결과로 만듭니다. 내부 프로토타입/기존 화면의 최소 연결부터 검증하고 정제 탭 전체 UI는 이어서 구현합니다.
3. 통화가 섞인 집계를 막고 요약은 전체 정제 입력의 같은 기간·통화와, TV 상세는 그 입력의 TV 부분과 대조합니다. 앞자리 0·중복 상세를 유지하고 오류는 사유와 함께 격리합니다.
4. 객체 키 순서만 바꾼 정의는 같은 해시, 단계/출력 열 순서를 바꾼 정의는 다른 해시임을 확인합니다. 정렬·서식을 고정한 결과의 재실행 동일성도 검사합니다.
5. 그 후에 승인·누적·공유 배포를 연결합니다. 첫 상태 구현은 현재 상태에 `승인 후 변경됨`을 더하는 정도로 시작하고 전체 상태 표현은 실제 흐름과 함께 확장합니다.

성능은 고객 자료를 외부로 보내지 않고 합성 자료와 승인된 현장 자료로 측정합니다. 입력 크기·행/열 수·기간·PC 사양·최대 메모리·디스크 사용량·처리시간·첫 미리보기·Excel 새로고침을 남깁니다. 아직 측정하지 않은 처리 속도를 약속하지 않습니다.

정식 릴리스는 A의 데이터 보호 문제를 먼저 다루고, 전체 검사·서명·Windows 설치·공유 폴더 및 Excel 현장 검수를 거쳐 판단합니다. 작업 계획 작성이나 테스트 통과만으로 새 개인 키 서명·실게시가 끝났다고 보고하지 않습니다.

## 10. Claude 논의에서 결정한 것과 남긴 것

- **합의:** 준비/집계/배포는 공통 데이터셋 계획을 편집하는 다른 화면이어야 하며 중간 CSV를 수동으로 계속 넘기는 구조를 피합니다.
- **제안 수정:** Claude의 최초 안은 공식 요약 정의를 배포 탭에 집중시키는 것이었습니다. 사용자 작업 흐름과 탭 복잡도를 고려해 재논의한 결과, **집계 탭에서 정의하고 배포 탭에서 고정 계획을 실행**하는 책임 분리로 합의했습니다.
- **합의:** 보존 기간 결정은 구조 설계의 선행 조건으로 강제하지 않습니다. 자동 삭제 없이 시작하고 실측 후 결정합니다.
- **합의:** 상세 보존·유니온·집계·조인은 서로 다른 작업이며, 합계 대조도 범위와 단위를 명시해야 합니다.
- **남긴 명칭 제안:** 상세 정의를 추가할 시점에 `집계·슬라이서`를 `집계·출력`으로 바꿀지 판단합니다. 현재 표시는 유지합니다.

다음 사용자 검토에서 정할 항목은 계획 진행을 막지 않는 선택입니다.

1. 우선 완성할 업무: 거래선 손익 요약과 TV 상세를 첫 검수 사례로 삼을지. 기본 제안은 이 두 결과입니다.
2. 격리/미분류 정책: 중요 키·기간·금액 오류는 차단을 기본 제안으로 하고, 단순 경고의 승인 조건은 데이터셋별로 합의합니다. 임의 허용률을 정하지 않습니다.
3. Excel 배포 크기: 우선 목적별 고정 CSV로 시작하고 연도별 분할·원본 보관 기간은 현장 크기/속도 확인 후 정할지. 기본 제안은 이 단계적 접근입니다.

## 11. 검수 증빙의 경계

Opus 논의는 실제 Claude CLI `claude-opus-5-5`의 응답을 사용했습니다. 첫 회차는 지정 소스·합성 화면, 두 번째는 첫 논의와 반론, 세 번째는 이 계획과 탐색 소스를 검토했습니다. 마지막 검토의 문구 보완(대조 범위·승인 스냅샷·해시·기존 정의 호환·첫 사례 축소)을 반영했습니다. 모델의 조언을 그대로 제품 사실로 간주하지 않고 숫자·동일 경로 위험은 별도 합성 사례로 확인했습니다. Claude가 테스트나 실제 업무 환경을 실행한 것은 아닙니다.

현재 변경의 직접 검증은 전체 Python 537개 실행·536개 통과·선택 Excel COM 1개 건너뜀, Qt 관련 17개 통과와 숨긴 Tk 창의 탭/버튼 순서 확인입니다. 이전 CSV 기본 탭을 가정하던 포커스 검사 한 개는 새 집계 기본 탭에 맞게 갱신한 뒤 전체 검사를 다시 통과했습니다. Tk 시작 선택 강조도 실제 초기 상태와 일치하도록 정리한 뒤 관련 94개 검사를 통과했습니다. 세 언어 제목·선택·입력 유지와 CLI v2.0.3 표시를 확인했으며 Ruff·차이 공백 검사도 통과했습니다. Windows 실화면/배율·실제 Excel·회사 공유 폴더·새 서명 설치본은 이번 검증에 포함하지 않았습니다.

입력 자료·UserSetting·인증서·사내 경로는 Claude에 제공하지 않았습니다. 논의에는 공개 소스와 합성 화면만 사용했습니다. 로컬 대화 응답·화면·재현·검사 로그는 Git 제외 `tools/`와 `build/`에 보존합니다. 이 문서는 원본 업무 파일이나 설치된 앱의 설정을 수정한 기록이 아닙니다.
