# 프로젝트 정리·저장 경로 검수 — 2026-10-06

대상: `feat/pyside6` 작업 소스. 설치 EXE 재배포나 GitHub 게시를 수행한 기록은 아닙니다.

## 확정 규칙

- 앱 설치: `%LOCALAPPDATA%\Programs\Data Refinery`.
- 설정·최근 작업·프리셋·로그: 위 경로의 `UserSetting`.
- 데이터셋 설정·작업 DuckDB: `UserSetting\datasets`.
- 공유 CSV·Excel 연결 경로와 설치 AppId는 유지합니다.
- 개발 규칙은 `AGENTS.md`, 상세 구조·이름 규칙은 `project-structure.md`, 코드 책임은 `AI_CODE_MAP.md`에서 관리합니다.

## 반영한 정리와 수정

- 동일 해시인 샘플 CSV·프로모션 템플릿 사본 두 개와 참조되지 않는 이미지 세 개를 삭제했습니다.
- 개인 지침 `myAGENT.md`는 `AGENTS.md`로 통합하고, 임시 검수 프롬프트는 삭제했습니다.
- 버전을 `src/version.py`로 통일하고 UI·CLI·빌드·spec·설치 테스트·릴리스 지침을 연결했습니다.
- 새 런처 출력 이름의 `Luncher` 오타를 `Launcher`로 수정했습니다.
- `src/app_paths.py`에서 UserSetting 경로와 최초 실행 이관을 관리합니다. 기존 설정·로그·프리셋·작업 DB는 임시 사본으로 복사하고 원본·사본 해시를 검증합니다.
- 기존 새 위치의 파일을 덮어쓰지 않으며, DB 읽기 잠금·WAL 검사·원본 변경 감지·완료 표식으로 이관 실패와 중복 이관을 방지합니다.
- 이관 잠금은 프로세스 종료 시 OS가 해제합니다. 작은 잠금 파일 자체는 재사용하므로 강제 종료 후에도 다시 이관할 수 있습니다.
- 설치 번들에서 UserSetting을 제외하고 Inno Setup `uninsneveruninstall`로 제거 시 보존을 지정했습니다.
- 레거시 집계 미리보기 재시도 콜백이 이미 해제된 exception 변수를 참조하던 오류를 수정했습니다.
- README 두 언어·지원 문서·데이터셋 사용법·코드맵·배포 문서를 같은 규칙으로 갱신했습니다.

## 검증 결과

- 실제 로컬 이관: 94개 파일 복사, 기존 세 디렉터리의 원본 해시 보존 확인. 원본은 백업으로 유지했습니다.
- 전체 회귀 테스트: 526개 실행, 525개 통과, 선택 실행 Excel COM 테스트 1개 건너뜀.
- 이관·설정·최근 작업·로그·데이터셋·인코딩 관련 테스트 41개 통과. OS 잠금 보완 후 이관·업데이트 테스트 14개 재확인 통과.
- 수정 Python 파일 린트 및 PowerShell 문법 검사 통과.
- 전체 린트의 남은 82개 항목은 해당 파일이 HEAD와 동일함을 대조하여 기존 항목임을 확인했습니다. 전체 린트 통과로 표시하지 않습니다.
- 임시 AppId·별도 설치 디렉터리로 만든 QA 설치본의 설치/재설치와 설정 보존을 확인했습니다. 운영 바로가기·기존 설치 삭제 작업은 QA 설정에서 제외했습니다.
- **제거 실행 미검증**: QA 제거 파일은 Windows Application Control 정책에 차단됐습니다. UserSetting 보존 설정과 CI smoke 검증 코드는 반영했으나 실제 제거 성공을 주장하지 않습니다.

## 남은 항목

- 기존 빌드 임시 파일·샘플 집계 출력·캐시의 직접 삭제는 자동 승인 검토가 정책상 차단했습니다. 상세 차단 사유는 제공되지 않았습니다.
- `scripts/clean_local_artifacts.ps1`는 검토용 목록을 기본 출력하며, 사용자가 `-Apply`로 실행하면 검증한 프로젝트 내부 생성물만 삭제합니다. 서명된 배포물·서명 기록·가상환경·UserSetting은 대상에서 제외합니다.
- 미서명 QA 제거 파일 정책 차단으로 임시 QA 설치 디렉터리와 독립 제거 등록이 남아 있습니다. QA 저장 경로·앱 식별자는 운영 설치와 구분됩니다. 정책이 허용하는 환경에서 QA 제거를 재검증해야 합니다.
- 이번 변경은 소스 기준입니다. 기존 설치된 EXE는 변경하지 않았으며 다음 빌드·서명·배포 시 새 경로 규칙이 실행 코드에 반영됩니다.
- 기존 린트 항목, 기본 실행 파일 고정 이름 도입, release/dist 구조의 대규모 이동은 후속 작업입니다.
