# Data Refinery v2.0.3 준비

- 탭 순서를 데이터 집계·슬라이서 → 데이터셋 배포 → 프로모션 템플릿 → CSV 구조 복구로 변경했습니다. 시작 화면은 집계 탭입니다. Tkinter 호환 화면도 같은 순서를 사용합니다.
- 한국어·영어·폴란드어 전환 시 실제 업무와 탭 제목이 일치하며 선택한 업무와 입력 설정을 유지하도록 연결했습니다.
- 기존 집계·배포 탭의 UI·UX, 데이터 마트 제작을 위한 정제 기능과 새 탭의 필요성을 검토하고 단계별 개선 계획을 문서화합니다. 정제 탭과 후속 기능은 제안 단계입니다.
- 버전 단일 출처는 `src/version.py`이며 설치·설정·작업 DB·공유 배포 경로와 기존 서명 파일은 유지합니다.

## 2026-10-16 데이터 보호 보강

- 집계 출력이 원본과 같은 실제 파일이면 엔진과 화면에서 차단합니다. 상대/대소문자 경로와 기존 파일 별칭도 검사하며 기존 결과 교체는 Qt에서 확인합니다. 미승인 결과가 작업 중 생기면 덮어쓰지 않습니다.
- 집계 화면에 `1,234.56` / `1.234,56 · 1 234,56` 숫자 표기 선택을 추가하고 프리셋에 저장합니다. 언어 변경 시 선택을 유지하며 표기 정보가 없는 예전 프리셋은 현재 화면 선택을 유지합니다.
- 잘못된 구분자·`N/A`·문자 `nan`·무한대·수치 범위 초과는 기본 엄격 모드에서 미리보기·저장을 중단합니다. 처음 감지한 검사 구간의 열·건수·예시를 알리고 이전 파일을 보존합니다. 예전처럼 잘못된 값을 0으로 합산하며 계속 진행하지 않습니다.
- 빈칸·`-`·실제 결측은 별도 건수로 표시합니다. 기존 계산 규칙대로 합계에서는 0, count/mean/min/max에서는 결측을 제외합니다. 수식 전용 원본 열도 표본과 전체 검사에 같은 기준을 적용합니다.
- 작은 집계 창은 스크롤로 모든 설정과 실행 버튼에 접근할 수 있습니다.

숫자 표기 선택은 사용자가 원본에 맞게 지정해야 합니다. `1.234` / `1,234`처럼 두 방식 모두 문법상 가능한 값은 자동 판별하지 않습니다. 괄호 음수·뒤쪽 마이너스 같은 미지원 회계 표기는 오류로 알립니다. 표본 통과는 전체 통과가 아니며 기존 float64 계산을 정밀 십진 계산으로 전환한 작업은 아닙니다. 새 숫자 표기 프리셋을 이전 앱에서 읽으면 그 정보가 무시될 수 있습니다.

이 문서는 소스 변경 기록입니다. 새 버전의 서명·설치 파일 빌드·실게시 완료를 의미하지 않습니다.
