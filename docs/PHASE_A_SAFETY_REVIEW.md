# A단계 첫 구현: 원본 보호·숫자 표기 검수

2026-10-16, 소스 준비 버전 2.0.3. [전체 개선 계획](DATA_PREPARATION_ROADMAP.md)의 첫 두 항목을 구현한 기록입니다. 이전 2.0.3 소스에 이어 같은 미게시 버전에서 작업하며 태그나 기존 서명 파일을 변경하지 않습니다.

## 구현한 동작

### 원본과 결과 파일 보호

- 엔진의 처리 전과 결과 확정 직전에 절대/실제 경로·Windows 대소문자·기존 파일 동일성을 확인합니다. 같은 원본 항목을 결과로 교체할 수 없습니다. 혼동 방지를 위해 원본을 가리키는 하드링크 등도 보수적으로 거부합니다.
- Qt의 파일명 칸에는 경로·Windows 대체 스트림·장치 예약 이름을 허용하지 않고 CSV/XLSX만 선택합니다. 저장 폴더도 확인합니다.
- 기존의 다른 결과를 교체할 때는 Qt에서 확인합니다. 확인하지 않은 출력은 Windows의 덮어쓰기 없는 rename으로 공개하므로 최종 확인 직후 새 파일이 생겨도 보호합니다. 실패한 임시 파일은 정리합니다.
- 직접 API의 기존 출력 교체 허용 기본값은 유지하지만 원본 보호를 끌 수는 없습니다. 임의 프로세스가 경로를 악의적으로 교체하는 모든 경쟁 조건을 제거했다는 보장은 아닙니다. 일부 NAS의 부정확한 파일 ID는 보수적인 차단을 유발할 수 있어 실제 공유 드라이브 검수가 필요합니다.

### 숫자 표기와 오류

- `English`: 쉼표 천 단위·점 소수, `Polish`: 점 또는 공백 천 단위·쉼표 소수. 일반/NBSP/좁은 NBSP 공백을 지원합니다. 구분자 제거 전에 묶음 자릿수를 검사합니다.
- 선택한 표기에 맞지 않는 값, 문자 `nan`/`inf`, 무한대·범위 초과를 차단합니다. 정상 유한 입력의 집계·수식 계산 중 생긴 범위 초과도 차단합니다.
- 기본 `strict_numeric=True`는 표본과 전체 실행에 적용합니다. 처음 발견한 잘못된 청크/표본의 열·건수·최대 세 예시를 구조화된 예외로 전달하며 전체 파일 오류 총건수로 표시하지 않습니다. 표본은 최대 2,000개 입력 행으로 한정됩니다.
- 검사 대상은 선택한 수치와 묶기·수식에 쓰는 원본 수치 열이며 조건 필터를 통과한 행입니다. 필터로 제외한 행이나 사용하지 않은 모든 열까지 검사했다고 표시하지 않습니다.
- 실제 결측·빈칸·`-`는 별도 건수로 표시하고 기존 집계 함수의 결측 규칙을 유지합니다. 문자열로 적힌 `nan`은 실제 결측과 구분합니다.
- Qt 오류 메시지는 세 언어로 표시하고 상태 라벨의 원본 예시는 HTML로 해석되지 않게 처리합니다. Tk/CLI의 엔진 진단은 기존 한국어 오류 경로를 사용합니다.
- 내부 API의 명시적 `strict_numeric=False`는 **오류 중단만 끕니다. 새 문법 검사는 그대로**이므로 예전의 잘못된 문자열 처리 결과까지 동일하게 재현하는 옵션이 아닙니다. Qt에는 이 완화 옵션을 제공하지 않습니다.

## 프리셋과 화면

- 새 프리셋은 선택한 표기 ID를 저장합니다. 언어를 바꿔도 표시명만 바꾸며 ID를 유지합니다.
- 표기 정보가 없는 예전 프리셋은 `None`으로 구분해 Qt/Tk의 현재 선택을 보존합니다. 직접 `to_spec`을 쓰는 경우만 기존 English 기본값을 유지합니다. 알 수 없는 명시적 값은 거부합니다.
- 가져오기·내보내기 미구현 메뉴, 기간 형식, 데이터셋 승인/배포 UI는 이 첫 구현의 범위 밖입니다. 정제 탭도 아직 추가하지 않았습니다.
- 합성 자료로 980×880, 820×720 Qt offscreen 화면을 확인했습니다. 작은 창은 내용을 잘라 압축하는 대신 스크롤하며 실행 버튼까지 이동하는 회귀 검사를 수행합니다. Windows 실화면·배율 검수와는 구분합니다.

## 검증 항목

- 원본과 상대·대소문자·하드링크 출력 경로: 거부 후 원본 바이트 보존.
- 처리 중 생긴 원본 별칭·미승인 결과, 마지막 검사 후 rename 직전 생긴 결과: 기존 바이트 보존·임시 파일 정리.
- 폴란드 숫자와 NBSP, 다른 표기/잘못된 묶음/비유한 값/미지원 회계 표기: 정확한 계산 또는 명시적 차단.
- 실패 전 존재한 결과 파일은 바뀌지 않음. 정상 결측은 함수 규칙대로 처리하고 건수 표시.
- 수식에만 쓰인 열도 미리보기와 전체 실행에서 같은 검사. 합계/수식 범위 초과 차단.
- 실제 디스크 프리셋 저장·로드, 예전 Tk 프리셋의 전역 숫자 표기 유지, Qt 세 언어·선택 유지.

실행 결과는 최종 소스의 자동 검사와 GitHub 검사 결과를 함께 확인합니다. 개인 키·업무 원본·설치된 UserSetting을 테스트 자료로 사용하지 않습니다. 새 서명·실제 Excel·회사 공유 드라이브·배포 성공을 이 소스 검수로 대신하지 않습니다.

전체 Python 회귀는 555개 실행·554개 통과·선택 Excel COM 1개 건너뜀입니다. 신규 안전성 12개, 프리셋 17개, Qt 집계 6개와 기존 엔진 81개도 별도로 통과했습니다. 첫 전체 실행에서 공유 번역키 검사가 Qt의 새 사용처를 포함하지 않아 실패했고, 실제 Qt 사용처까지 검사하도록 확장한 뒤 전체 회귀를 다시 통과했습니다.

## Opus 검토와 조치

실제 Claude CLI `claude-opus-5-5`로 설계·구현·후속 검토 세 회차를 완료했습니다. 구현 검토는 P0/P1 차단 문제는 없다고 판단했고, 예전 Tk 프리셋이 전역 표기를 바꾸는 P2를 지적했습니다. 누락 필드와 명시적 표기를 구분하고 Qt/Tk 회귀 검사를 추가했습니다. 오류 표시·동시 출력·엄격 모드의 동작 변화도 반영했습니다. 최종 읽기 전용 검토는 이 회귀가 해결됐고 P0/P1·필수 수정 P2가 없으며 전체 검사 통과를 조건으로 이번 단계가 준비됐다고 판단했습니다. 모델의 소스 검토와 직접 실행한 검사를 구분하며 응답과 로그는 Git 제외 `tools/`에 보존합니다.

## 남은 한계와 다음 작업

- `1.234`, `1,234`의 의도는 문법만으로 판단할 수 없습니다. 사용자가 표기를 선택하고 샘플 및 전체 수치를 확인해야 합니다.
- float64 계산의 정밀도는 유지합니다. 금액별 십진 정밀도 계약과 교차 출력 대조는 후속 단계입니다.
- 다음 A 작업은 기간 형식 저장/검수 일치, 경고·기간별 합계 노출과 명시적 승인/백그라운드 배포입니다. 이를 확인한 뒤 정제·출력 정의의 작은 로컬 사례로 진행합니다.
