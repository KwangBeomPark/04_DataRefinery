# 공통 정비 3–5단계 검수 (2026-10-08)

## 변경과 보호

- 업데이트 설정, 데이터셋 정의, 프리셋과 최근 작업은 같은 폴더의 고유 임시 파일에 완전히 쓰고 flush/fsync/닫은 후 교체합니다. 실패 후 원본에 직접 쓰는 경로를 추가하지 않았습니다. 다른 작성자의 임시 파일을 삭제하지 않습니다.
- 일반 settings.json은 쓰기 직전에 기존 내용을 UTF-8 JSON object로 검증합니다. 손상/잘못된 형식/읽기 권한 실패를 기본값으로 덮어쓰지 않고 OSError로 차단해 원본을 보존합니다. 조회의 기본값은 표시용 fallback이며 복구 저장의 허가가 아닙니다.
- 최근 작업은 기존 편의 복구를 유지하면서 손상 내용을 고유 `.bak`에 flush/fsync한 뒤 원본 bytes와 비교합니다. 읽기/사본 보존/검증 실패는 저장을 건너뛰고 본 업무는 진행합니다. 범용 원자 저장에 일괄 JSON 형식 제한을 넣지 않아 명시적인 프리셋 덮어쓰기와 기존 list 형식은 유지합니다.
- 명시한 `false`·포트 값은 기본값으로 덮어쓰지 않습니다. 데이터셋 정의 저장·삭제 실패 시 기존 정의와 작업 DB를 유지합니다. 교차 검수에서 발견한 기존 읽기 오류를 빈 목록으로 숨기는 경로도 저장·삭제에서는 실패를 전파하도록 보완했습니다. 최근 작업과 UI 목록 조회의 기존 실패 처리 계약은 유지합니다.
- 공통 백업은 UserSetting 전체(설정, 최근 작업, 프리셋, 로그, 데이터셋 정의·DB와 이관 표식)를 포함합니다. `SettingsOnly`는 datasets을 제외합니다. 외부 원본·배포 파일과 사용자 지정 외부 저장소는 별도 백업 대상입니다. 상세 계약은 [USER_DATA](USER_DATA.md)에 있습니다.
- 설치 설계의 위치를 `installer/`로 안내하는 공개 [CODE_MAP](CODE_MAP.md)을 추가했습니다. `docs/project-structure.md`의 검수 전 사용자 수정은 보존하고 오래된 설치 참조를 정정했습니다. 기존 구조 원문을 이전 메모로 표시하고 현재 installer/build/dist/release 역할을 별도 안내했습니다. README 두 언어와 로컬 역할 지도를 보완했습니다.
- 실제 항목이 업데이트·저장소·정보인 Qt 메뉴를 `업데이트 / 정보`로 표시하고 세 언어 이름을 제공합니다. 버전 표시는 제품 버전만 표시합니다. 제품명·버전·식별자·업무 기능을 변경하지 않았습니다.
- 빌드 테스트 게이트에 공통 백업 회귀를 연결했습니다. 소스 회귀의 LOCALAPPDATA와 APPDATA는 임시 검사 경로로 격리합니다.

## 검증

- 전체 Python 회귀 **536개 실행, OK (2 skipped)**. Excel COM은 명시적 실제 환경 검수 대상, 설치 Pascal harness는 컴파일 후 Windows Application Control의 미서명 실행 차단으로 skip입니다. skip을 동작 통과로 계산하지 않습니다.
- 원자 저장·데이터셋·프리셋·최근 작업·업데이트 집중 회귀 46개 통과. flush/교체 실패, 원본 바이트·다른 임시 파일 보존, 명시값 유지, 삭제 실패 후 DB 유지 확인.
- 이후 일반 설정의 손상 JSON·배열 root·잘못된 UTF-8·읽기 잠금 상태에서 fallback을 저장해도 원본 bytes를 유지하는 추가 회귀를 전체 검사에 포함했습니다.
- Windows PowerShell 5.1 공통 백업 최종 **34개 safety assertion** 통과. 실제 UserSetting을 읽지 않는 격리 사본 검사입니다. 독립 읽기 검수에서 settings-only의 제외 목록·실제 멤버 불일치를 보고했고 총괄이 검증과 실패주입 회귀를 추가한 최종본을 재검수했습니다.
- 변경 Python에 Ruff E4/E7/E9/F 통과, src/tests/installer 구문 컴파일, 빌드 스크립트 PowerShell 구문 검수와 git diff --check 통과.
- 근거는 로컬 무시 경로 `build/standardization/final-f1c054ca64e642e89eb2d1308c988e82/unittest.log`에 있습니다.

## Gemini 활용과 독립 판단

Antigravity CLI `gemini-3.8-flash-high`, effort high의 짧은 도구 없는 원자 저장 초안 요청이 **59.24초에 비어 있지 않은 응답으로 완료**됐습니다. 요청·응답·UTC·종료 상태는 `build/standardization/agy/atomic-settings-draft.json`에 기록했습니다. 고유 임시 파일/flush/fsync/교체 패턴을 참고했고 응답에 가정한 `_encrypt` API는 실제 코드 계약과 다르므로 사용하지 않았습니다. 구현은 직접 검수하고 실패주입 테스트로 확인했습니다. 다른 요청의 시간 초과·빈 응답은 완료 근거에 포함하지 않습니다.

별도 담당이 원자 저장과 데이터셋 삭제 순서를 읽기 교차 검수했습니다. 목록 읽기 오류를 빈 목록으로 간주하는 기존 공백을 지적해 엄격한 저장용 읽기와 손상 JSON/스키마/권한 실패 후 원본·DB 보존 검사를 추가했습니다. 구조 문서 원문 보존은 최소 경로 정정 후 역치환 SHA-256이 검수 전 `57BAF13077DAA77DC19D6A39D337E3C21E669F3D6B7398D18BE3EC8F24064643`과 일치함을 확인한 뒤 이전 메모 표기와 현재 역할 안내만 추가했습니다.

실제 서명·게시·설치/업그레이드·제거·네트워크/Excel/DB 동시 사용과 수동 화면 검수는 실행하지 않았습니다. 전체 미서명 제품 패키지도 새로 만들지 않았습니다. 설정·외부 원본·기존 서명 배포물·키와 설치 식별자는 보존했습니다. 실제 배포 전 잠금/저장 공간 부족 및 DB 종료 후 백업·새 폴더 복원과 대표 작업을 확인해야 합니다.
