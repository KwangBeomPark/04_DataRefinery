# Data Refinery 주요 개발계획

작성일: 2026-11-03

상태: 사용자의 추가 요청에 따라 용량 관리와 Claude Opus 5.5의 총 4회 논의를 반영했다.
이번 문서는 범위와 사용자 흐름을 정리한 계획이며 구현·검수 완료 기록이 아니다.
구체적인 계약·단계·검증은 [상세 개선계획](FLEXIBLE_DWH_IMPROVEMENT_PLAN.md), 수용·수정 사유와 증빙은 [Opus 논의 기록](FLEXIBLE_DWH_OPUS_REVIEW.md)을 따른다.

## 1. 목표와 전체 흐름

원본마다 차원·팩트·관계를 정의하고, 생성한 DB를 앱에서 확인한 뒤 목적별 CSV를 SharePoint로 배포한다.
손익·매출·매출차감·재고 등에 적용하며, 손익은 첫 번째 검증 사례와 템플릿으로 사용한다.
차원 이름·개수·키와 팩트 구조를 손익 전용으로 고정하지 않는다.

```mermaid
flowchart LR
    A[원본 연결·구조 확인] --> B[차원·팩트·관계 정의]
    B --> C[로컬 DuckDB 생성·검사]
    C --> D[목적별 데이터셋·CSV 생성]
    D --> E[회사 SharePoint 배포]
    E --> F[Excel 새로고침·피벗 분석]
```

- DuckDB 작업 DB는 제작자 PC에서 관리한다. 최초 생성 후 같은 DB에 기간별 자료를 누적·갱신하며 검사·CSV 추출이 앱 안에서 이어지게 한다.
- 팀원에게는 검수한 목적별 CSV와 Excel 연결 방법·템플릿을 제공한다.
- 팀원은 추가 DuckDB·Python·ODBC 드라이버 설치 없이 Excel 기본 기능으로 이용한다.
- Excel은 새로고침으로 데이터를 받고, 내려받은 범위 안에서 피벗을 조작한다.

## 2. 주요 개발 범위

| 영역 | 사용자 작업 | 목표 결과 |
| --- | --- | --- |
| 원본 연결 | 파일·폴더를 지정하고 열·형식·기간·단위를 확인 | 원본을 보존하는 반복 입력 정의 |
| 데이터 모델 설계 | 원본 열을 차원으로 묶고 업무 키·속성·측정값·관계를 지정 | 저장하고 재사용할 수 있는 모델 정의 |
| DB 생성·누적·검수 | 최초 생성 후 새 기간 추가·수정 범위 교체와 구조·관계·원본 대사를 확인 | 과거 기간을 보존하고 검수 결과가 연결된 로컬 DuckDB |
| 용량·성능 관리 | 운영 한도·DB/WAL 크기·디스크 여유·증가량·처리시간 확인 | 80% 경고와 다음 적재의 공간 점검, 보관·분할 검토 근거 |
| 분석용 데이터셋 | 기간·분석 수준·필터·지표를 선택하고 미리보기 | 모델 하나에서 여러 목적별 CSV 생성 |
| SharePoint 배포 | 사이트 주소를 입력하고 회사 계정으로 로그인 | 지정한 배포 작업의 파일 업로드·완료 확인 |
| Excel 연결 | 연결 설정이 준비된 템플릿을 공유하고 새로고침 | 각자 저장한 Excel에서 추가 분석 |

## 3. 유연한 차원·팩트와 키 관리

- 원본 열을 선택해 차원을 만들거나, 정의가 같은 기존 차원에 연결한다.
- 이번 수익성 모델은 거래선과 Ship-to를 하나의 차원으로 묶는다. 다른 모델에 같은 조합을 강제하지 않는다.
- 월·일 등 시간 수준은 원천에 맞춘다. 월간 자료를 임의의 일별 거래로 바꾸지 않는다.
- 차원에는 대리키를 발급하고 원래 업무 키도 보존한다. 기존 대상의 키는 재실행·다음 달 적재에서 유지한다.
- 팩트는 먼저 실적 한 행의 의미를 정하고 필요한 차원의 키를 참조한다.
- 팩트의 중복 방지 기준은 해당 업무의 행 단위로 정한다. 외래키 조합이 항상 유일하다고 가정하지 않는다.
- 매출·차감·재고 등의 팩트는 각자 적절한 단위로 만들고, 의미·키 정의가 같은 차원을 재사용한다.
- 지표마다 합계·잔액·비율 등의 집계 방법을 둔다. 재고 잔액을 날짜에 걸쳐 단순 합산하지 않는다.
- 가로 지표 유지와 세로형 항목 전환은 원본·목적에 따라 정한다. 모든 입력에 손익용 변환을 적용하지 않는다.
- 모델·업무 키를 변경할 때 기존 데이터와 대리키에 미치는 영향을 확인한다.
- 과거 월 수정이 최신 거래선·제품 속성을 되돌리지 않게 기준시점/권위 원천을 정한다. 같은 시점의 상충은 확인 없이 덮어쓰지 않는다.
- 새 비용 열·이름 변경·필수 열 누락은 대조 화면에서 처리한다. 새 지표의 과거 미보고 값을 0으로 채우지 않는다.
- 다른 작업 공간에서는 차원 설계 틀을 복사해 쓴다. 차원 데이터·대리키는 각 공간 소유이며 동일한 키 번호만으로 DB를 서로 연결하지 않는다.

첫 수익성 검증 사례의 단위는 금액 USD(배율 1), 수량 QTY(배율 1)이며 원본 소수점을 보존한다.
이 단위는 해당 모델의 설정으로 저장하고 다른 원본에 자동 적용하지 않는다.

### 월별 누적과 수정 자료 처리: 필수 요구사항

기본 작업은 기존 DB에 대한 증분 반영이다. 매달 빈 DB나 현재 월만 있는 팩트로 재생성하지 않는다.

| 입력 상황 | 처리 원칙 |
| --- | --- |
| 최초 1월 자료 | 모델에 맞춰 최초 DB를 만들고 1월 적재 |
| 새 2·3·4월 자료 | 기존 월을 유지하면서 새 기간 추가 |
| 이미 반영한 같은 자료 재실행 | 같은 자료·변환 정의를 중복 누적하지 않음 |
| 수정된 2월 자료 | 검수한 교체 범위의 2월 자료만 갱신하고 1·3·4월 보존 |
| 오류·불완전한 수정 입력 | 교체를 확정하지 않고 이전 성공 자료 보존 |

- 교체 범위는 모델·팩트·법인·기간과 원천의 분할 범위를 기준으로 정한다. 같은 달이라는 이유로 다른 업무나 분할 자료까지 지우지 않는다.
- 여러 파일이 한 월을 구성할 때 일부 파일만 받은 상태에서 해당 월 전체를 교체하지 않는다.
- 월 완성본과 일부 추가·변경 거래만 담긴 입력은 구분한다. 증분 거래의 식별·취소·갱신 규칙은 상세 계획에서 정의한다.
- 누적 시 기존 차원 대리키는 유지하고 새 대상에만 새 키를 발급한다.
- 원본·적재 이력과 기간별 행 수·금액·수량을 보존하고, 변경 전후 차이와 추가/교체/중복 제외 범위를 화면에 보여준다.
- 1~4월 적재 후 수정 2월 재처리, 동일 자료 재실행, 부분 입력과 실패 시 보존을 필수 검증 사례로 둔다.
- 전체 재구축은 기본 월간 처리와 구분한 별도 관리 작업으로 설계한다. 보존 기간에 따른 자동 삭제는 이번 단계의 기본 동작으로 넣지 않는다.
- 첫 구현은 확정 전 롤백과 완성 입력을 이용한 정정을 지원한다. 확정된 적재를 임의 시점으로 되돌리는 기능은 두지 않는다. DB 전체 손상은 일관 백업/검증된 복원 지점으로 별도 관리한다.
- CSV는 누적 DB에서 선택 기간 전체를 다시 추출할 수 있다. CSV 완성본 재생성과 DB 과거 자료 삭제를 구분한다.

### 용량과 성능 관리: 필수 요구사항

- 첫 구현은 모델 하나를 작업 공간 하나에서 관리하고, 작업 공간별 활성 DB 운영 한도를 설정한다. 한도는 실측 후 결정하며 임의의 연간/3개년·고정 GB 한도로 단정하지 않는다.
- 활성 DB와 WAL 크기 합계가 설정 한도의 80% 이상이면 경고한다. 예산을 설정하지 않았거나 측정이 불완전하면 임의의 사용률·정상 판정을 표시하지 않는다.
- 예를 들어 한도 10 GiB이면 8 GiB부터 경고한다. 설명용 예시이며 DuckDB의 최대 크기나 속도가 급격히 떨어지는 경계가 아니다.
- 화면에 DB/WAL, 전체 작업 공간, 디스크 가용 공간, 월별 증가량, 적재·CSV 생성 시간, 메모리/임시 공간과 측정 시각을 구분해 보여준다.
- 새 월 적재 전에는 임시 작업·복구 자료·출력을 포함한 피크 공간을 점검한다. 실제 부족은 쓰기 차단이며 운영 예산 경고와 구분한다.
- DB의 80%에서는 예산·디스크·보관/분할 검토를 안내한다. 자동 삭제·자동 분할은 하지 않고, 나중에 분할해도 같은 작업 공간의 합계를 계속 관리한다.
- 대응 화면을 활성 DB / 원본·이력 등을 포함한 작업 공간 / Excel용 CSV로 나눈다. CSV 축소가 DB 크기 경고를 해소한다고 안내하지 않는다.
- 속도는 같은 규모의 처리시간과 자원 사용을 비교해 판단한다. 단순 파일 분할만으로 빨라진다고 보장하지 않는다.

## 4. 앱 안에서 보이는 설계와 검수

첫 번째 작업 공간에서 다음을 연결한다. 별도 DB 도구 설치를 기본 사용의 필수 조건으로 삼지 않는다.

- 원본 열과 고유값·빈값·자료형을 보는 영역.
- 사용자가 정의한 차원·팩트 카드와 PK/FK·관계를 보는 영역.
- 선택한 테이블의 키·속성·측정값·집계 규칙을 설정하는 영역.
- 생성 전 표본과 생성 후 실제 테이블의 행 수·열·데이터를 보는 영역.
- 중복 키·미연결 키·예상하지 않은 행 증가·기간·형식 오류를 확인하는 검사 결과.
- 원본과 DB의 수량·금액 및 제외·변환 내역을 나란히 확인하는 대사 결과.

관계도는 실제 DB 구조와 일치하게 한다. 표본 미리보기와 전체 검사 결과를 구분한다.
차원 중복 제거·손익 항목 전개처럼 정상적으로 행 수가 변하는 작업도 변환 규칙에 맞춰 검증한다.
문제가 있으면 해당 원본·규칙으로 이동해 수정하고 재실행할 수 있게 한다.

## 5. 목적별 CSV 생성

DB 모델과 CSV 출력 정의를 분리한다. 사용자에게 SQL 작성을 기본 요구하지 않는다.

- 출력 이름, 대상 모델, 분석 수준, 기간·필터, 표시할 지표와 집계 규칙을 저장한다.
- 같은 DB에서 거래선 월별 요약·모델 상세·비용 내역 등 여러 출력을 만든다.
- 요약에서 제거한 상세는 해당 CSV로 복원할 수 없으므로 목적에 맞는 데이터셋을 제공한다.
- 미리보기·전체 검수 후 완성본을 생성한다. 사용자가 중간 CSV를 탭 사이에 반복해서 옮기는 흐름을 줄인다.
- 다음 원본 반영 후 같은 출력 정의를 다시 실행할 수 있게 한다.
- 기존 파일 기반 빠른 집계와 CSV 누적·배포 기능은 호환을 유지하며 점진적으로 연결한다.

## 6. SharePoint 배포: 사이트 주소를 기본 입력으로

- 사용자가 입력하는 기본 배포 주소는 **SharePoint 사이트 주소**이다.
- 회사 계정 로그인과 해당 배포 위치의 쓰기 권한은 별도로 확인한다.
- 사이트 내부 라이브러리·폴더는 앱의 탐색·기본값·저장된 배포 설정으로 관리한다.
  여러 대상이 있을 때 자동 결정과 최초 선택을 어떻게 구성할지는 상세 계획에서 정한다.
- 공통 배포 연결을 재사용하면서 데이터셋·배포 작업별 대상과 파일명을 관리한다.
- Excel 연결을 유지할 출력은 고정 경로·파일명·열 구조로 갱신한다.
- 업로드 완료·실패를 확인하고, Excel용 원본 연결 정보나 템플릿을 제공한다.
- 실제 회사 주소·인증정보를 공개 소스에 하드코딩하지 않는다. 사내 설정은 AGENTS.md의 중앙 관리 원칙을 따른다.
- 인증 방식·회사 승인 조건·업로드 재개·갱신 중 조회 일관성은 상세 설계와 실제 환경 시험에서 확정한다.

사이트 주소만 입력하면 로그인·권한·배포 대상 검증이 자동으로 생략된다고 가정하지 않는다.

## 7. 화면과 기존 구현의 정비 방향

- 첫 번째 중심 업무: 원본 연결 → 구조 설계 → 공간 점검 → DB 누적·갱신 → 관계·결과·용량 검수.
- 두 번째 중심 업무: 목적별 데이터셋 정의 → CSV 검수 → SharePoint 배포 → Excel 연결.
- 빠른 파일 집계와 정제 도구는 보조 업무로 유지한다. 탭을 계속 늘리기보다 기존 화면 안의 단계를 명확히 한다.
- 모델 정의, 출력 정의, 배포 설정을 각각 저장하고 연결한다.
- 기존 엔진과 영속 대리키 등록부를 검토해 재사용한다. 기존 DB·설정·연결을 보존하며 단계적으로 전환한다.

현재 v2.7.0 소스는 DWH 생성·제한된 결과 미리보기·별도 CSV 누적/배포·파일 집계가 나뉘어 있다.
범용 모델 편집·DB 관계 검수·DWH에서 목적별 CSV로 이어지는 흐름·SharePoint 직접 업로드는 보강 대상이다.
이 문서를 현재 앱의 구현 완료 기능으로 안내하지 않는다.

## 8. Opus 4회 논의를 반영한 상세 계획

1. 재사용할 모듈과 현재 고정 처리의 변경 범위, 기존 DB·설정의 호환·전환 방법.
2. 모델·키·출력 정의의 저장 구조와 버전 관리, 적재·수정 월 재처리 규칙.
3. 실제 사용자 화면 흐름과 모델 카드·관계도·검수 결과의 구체적인 구성.
4. SharePoint 사이트 주소에서 배포 대상을 확정하는 UX와 인증·업로드·Excel 연결 방식.
5. 구현 단위·의존 순서·완료 기준과 수익성 외 업무를 포함한 검증 사례.
6. 작업 공간별 80% 경고·측정 실패·디스크 사전 점검, 복구와 보관·분할의 경계.
7. 과거 속성 회귀·원본 구조 변경·다른 공간의 키 충돌·일반 피벗의 잘못된 합산 방지.

최초 범위는 기본 차원·팩트 정의, 안정적인 키, 기간별 누적·수정 범위 재처리, 눈으로 확인하는 구조·검수, 목적별 CSV,
SharePoint 배포 흐름과 용량·성능 지표로 잡는다. 복잡한 값 매핑·분류 규칙과 고급 이력, 자유 드래그 편집·실제 보관/분할 도우미는 확장 항목으로 둔다.
입력 폼으로 차원·팩트를 정의하고 자동 관계도를 제공하는 순서로 단순화했다.
첫 수직 시제품은 단일 팩트의 가산 지표를 중심으로 첫 적재→다음 월→수정 월→대사→CSV→배포를 연결한다. 비용 세로형에는 반복 QTY를 넣지 않는다.
비율은 분자·분모를 제공하고 재고는 단일 기준기간부터 시작한다. 여러 기간 재고·피벗 비율은 실제 Excel 측정값/템플릿 검증을 거쳐 확장한다. CSV만으로 일반 피벗의 집계를 강제할 수는 없다.
작업은 순차 실행하며, 최소 설정 마법사를 누적 엔진과 함께 제공한다. 팀원의 추가 설치는 요구하지 않는다.
계획과 4회 논의 기록을 작성한 상태이며 앱 구현은 시작하지 않았다. 로컬 DuckDB 로딩 차단은 정책 우회 없이 실행 환경 확인 항목으로 남겼다.
